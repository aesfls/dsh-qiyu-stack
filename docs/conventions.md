# 默认值里不许有「别人的东西」

这条是踩了一脚才写下来的。

## 教训

`dsh-bili-subagent` 里有个字段 `ownerName`（设置页叫「称呼」），代码里写着：

```js
ownerName: z.string().default('小鱿鱼')
```

`小鱿鱼` 是插件作者自己的称呼。它不只是个默认值 —— 它被写进了用户的
`cordis.patch.yml`，而配置优先级是「设置页 > 插件 config.json > 代码默认值」，
于是用户打开设置页，看到的是**一个自己从没设过的名字**，还以为是自己填错了。

**一个默认值，能让用户对自己的配置产生怀疑。**

## 规矩

| 层 | 放什么 | 例子 |
|---|---|---|
| **代码默认值** | 空的，或对任何陌生人都成立的中性值 | `port: 0`、`container: 'napcat-qq'`、`音色: ''` |
| **模板** | 空字段 + 说明「这里填你自己的」 | `templates/blank/character.json` |
| **本机配置** | 用户自己的真实值，且**不进版本库** | `qiyu.config.json`、`characters/<名字>/` |

## 对用户说的话，还有两条硬规矩

### ⓪ 三份 `AGENTS.md`，各管各的，绝不许串

这个项目里有三份同名文件，搞混了就是事故（会把"部署指令"喂给正在聊天的角色）：

| 文件 | 谁读 | 影响范围 |
|---|---|---|
| `~/.dsh/AGENTS.md` | **所有** DSH 会话 | ⚠️ 最广，连别人家已经养着的角色都会读到 |
| `characters/<名字>/AGENTS.md` | 那个角色自己的会话 | 性格、语气、边界 |
| `dsh-qiyu-stack/AGENTS.md` | **只有工作目录在这个仓库里的会话** | 只影响"正在装机的助手" |

规矩：

- **仓库根那份**开头必须有作用域声明：「如果你是被部署出来的角色，忽略本文件」
- **任何工具都不许改** `~/.dsh/AGENTS.md` 和已存在的 `characters/<名字>/AGENTS.md`
- `qiyu install` 只从角色包拷三个文件，**不读仓库根**——所以物理上也串不过去

### ① 「重启」必须带宾语

用户看到「重启一下」会愣住：重启电脑？重启 DSH？重启 Docker？

所以每一处都写清**重启的对象和范围**：

| 场景 | 该怎么说 |
|---|---|
| 装完 Docker Desktop | 「重启**这台电脑**（不是重启 DSH）」 |
| 装完插件 / bundle | 「重启 **DSH**：把窗口关掉再打开（不用重启电脑）」 |
| 改了容器配置 | 「重启**容器**：`docker restart <名>`（不用重启电脑）」 |
| 改了 client.js 样式 | 「**刷新页面**（Ctrl+R）就行，不用重启」 |

### ② 会自动弹窗的动作，必须提前说清「弹的是什么」

用户最怕的是：莫名其妙跳出来一个页面，上面问要 token。

所以凡是会自己打开东西的地方，**先一句预告，再动手**——而且要说到「这是什么、为什么要它」：

- **二维码**：「会弹出 QQ 的登录码（图片窗口）。用你要登的那个号拿手机 QQ 扫它，扫完那个号就登进容器了，之后别人发消息才会走到你这边。」
  （只说「弹出一张二维码」不够——用户不知道扫码是在干什么。）
- **启动 DSH**：「DSH 启动时可能自己弹一个浏览器窗口，那是它自己的界面，不是报错；里面的 QQ 设置已经填好了，不用改。」
- **NapCat 的 WebUI**：能不提就不提。真要提，一句话说清「日常用不到、只监听本机、token 在哪」。
  实测：NapCat 容器里没有浏览器，它自己**不会**开弹窗；用户看到的窗口多半是 DSH 开的。

反面例子（真实发生过）：用户第一次部署，浏览器弹出 NapCat 的 token 输入页，他不知道那是什么、也不知道 token 在哪，只能来问。

## 一个值能不能当默认值？问一句：

> **换一个陌生人来装，这个值还对吗？**

对 → 可以。不对 → 不能。

| 值 | 能不能当默认 | 为什么 |
|---|---|---|
| OneBot HTTP 端口 `3000` | ✅ | 是 OneBot 的惯例，人人都用 |
| DSH 端口 `55861` | ❌ | 每台机器随机分配，这里是作者的 |
| 容器名 `napcat-qq` | ✅ | 中性，谁装都叫这个 |
| 容器名 `my-bot-container` | ❌ | 作者自己起的名字 |
| 音色 `zh-CN-XiaoxiaoNeural` | ✅ | edge 的通用女声 |
| 音色 `zh-CN-XiaoyiNeural` | ❌ | 作者给某个角色选的 |
| 转写脚本 `D:\某人\语音转写.py` | ❌ | 作者的盘符和目录 |
| 称呼 `小鱿鱼` | ❌ | 作者本人 |

## 实测踩到的「漏出来」清单

这些是真的从别人机器上漏进过配置的：

- `ownerName: 小鱿鱼` —— 作者称呼，出现在设置页
- `转写脚本: D:\某人\语音转写.py` —— 作者路径，写死在代码默认值里
- `if (uid === 10001)` —— 作者角色的 QQ 号，写死在逻辑里
- `表情目录: D:\某人\表情包` —— 作者路径

前两条已经改成读配置；后两条由使用者在 `character.json` 里填自己的。

## 那「示例」怎么办？

想让人看懂格式，又不想漏私人值：

1. **用明显假的**：`123456789`、`C:\path\to\file`、`某甲 / 某乙`
2. **放 `examples/`，默认不加载**，并在 README 里说明「这是样板，不是默认值」
3. **说明文字里提一句**「比如：小鱿鱼」——只要它只是文案、不是值

## 自检

`qiyu doctor` 会扫一遍 `templates/`，看到这些就报警：

| 规则 | 抓什么 |
|---|---|
| `[A-Z]:\\(Users|AI)\\` | 别人的本机路径 |
| `云千语\|小鱿鱼` | 作者的角色名 |
| 连续 8–11 位数字 | 像 QQ 号的数字 |
| `SESSDATA` / `mQ-…` | 令牌 |

扫不到东西会显示：**模板体检通过：没有别人的私人值**。

## 给插件作者的一条建议

写 `default` 之前，把「我自己的值」从手指底下挪开：

- `default('')` 永远比 `default('我的名字')` 安全
- 想给用户看格式 → 写在 `description` 里，不是写在 `default` 里
- 配置项一旦落盘，用户很难分清「这是我设的」还是「插件给我的」
